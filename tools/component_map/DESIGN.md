# Component Map: page and figure design

Date: 2026-09-21. Status: approved, awaiting implementation.

## Goal

Replace the card-based Component Map page with one generated figure that shows every IAMLab component, how it hangs off the main slicing route, and nothing else. No explanations in the figure. One sentence on the page.

## Decisions

| Topic | Decision |
|---|---|
| Relations shown | Bold spine Geometry → Slice → Place → G-code Generator. Every other component attached by one thin arrow to the core node it feeds or reads. No text on arrows. |
| Grouping | None. No frames, no headings. Placement by connection: inputs above the spine, readers below, calibration row at the bottom, utilities bottom-left. |
| Node content | Icon + name only. No ribbon-group tag, no description, no family colour. |
| Geometry input | One `Geometry` node with the Grasshopper Geometry parameter icon at the start of the spine. Not linked. Test Geometry sits above it with a thin arrow into Slice. |
| Machine Console | Directly under Generator, own direct arrow (2.2 px), box styled like a spine node. Live View and Machine Files hang off it. |
| Manual steps | Dashed arrow only: DoE Design ⇢ RSM Evaluate. No placeholder node. |
| Settings feedback | Dashed lines from Desirability and Pareto Select merge and run up the right edge into Generator. |
| Utilities | Load Settings and Version stay on the map, unattached, bottom-left. |
| Style | S2 outline monochrome: white fills, dark stroke and bold 14 px text for spine and Console, light gray stroke and 13 px text for satellites, gray arrows. Only the icons carry colour. Hover and focus turn a box's stroke and name link blue (`#28699f`). |
| Orientation | Horizontal spine at column width. Canvas 800 × 770 viewBox. |
| Figure technology | Inline SVG generated by a script from a JSON spec. Boxes are links to the component pages. |
| Page text | Title, then "Click a component to open its page.", then the figure. |
| Sizing | The SVG fills the content column up to 880 px and scales down to 600 px; below that the wrapper scrolls horizontally. The content column itself is widened to 64rem in `_sass/custom/setup.scss`. |
| Old draw.io master | Deleted. |
| Old card include, CSS, 24 px PNG icons | Deleted. |

### Edges

| Style | From → To |

Rule: one arrow per satellite to its primary core node. Secondary connections that exist in the plugin but are not drawn: Print Bed → Robot Simulation and Live View, Robot Definition → Robot Simulation, Print Stats and Machine Console, Interlayer Time → Legend, G-code Restart → Save G-code and Machine Console, Test Geometry → calibration prints.

### Icons

Sources copied into `assets/images/icons/svg/`:

- 22 plugin icons from `IAMLabSlicer/Resources/icons-src/IAMLab/*.svg` (24 px viewBox), unchanged.
- `GhGeometry.svg`: the Grasshopper Geometry parameter icon from the grasshopper-icons set, unchanged.
- `IamVersion.svg`: redrawn as vector (blue circle, check mark), same look as the plugin's runtime-drawn icon. The plugin has no SVG source for it.

The generator inlines each icon as a nested `<svg viewBox>` and prefixes every `id` (and its `url(#…)` / `href="#…"` references) with the icon name so gradients cannot collide.

### Accessibility and interaction

- Root `<svg>` has `role="img"` and `aria-labelledby` pointing at a `<title>` "IAMLab Slicer component map".
- Hover and `:focus-visible` on a link: box stroke and name turn `#28699f`, stroke width 2.4.
- Font: `font-family: inherit` so the theme font renders.

## Generator

`tools/component_map/`:

- `component-map.json`: nodes and edges as listed above, pixel layout included.
- `build_component_map.py`: Python 3, stdlib only. Reads the JSON and the icon folder, writes `_includes/component-map.svg`. Fails with a clear message on a missing icon or unknown node id.
- `README.md`: how to edit the JSON and rerun.

Run from the repo root:

```
python tools/component_map/build_component_map.py
```

The generated include is committed. `tools/` is excluded from the Jekyll build.

## Verification

No Ruby in this environment, so no Jekyll build. Checks that run:

1. Generated SVG rendered standalone with headless Edge, baseurl substituted for the Liquid filter; visual check of layout, labels, arrows.
2. Every link slug matches an existing `docs/components/iamlab-<slug>.md`.
3. All `id` attributes in the generated SVG are unique.
4. No remaining references to `component-card`, `component-grid`, `_24.png`, `assets/diagrams` in the repo.
5. `tools/check_site.py` after the next Jekyll build validates the links from the inline SVG like any other page links.
