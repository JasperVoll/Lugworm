# Changelog - Week 6, 20-08-2026, V. 1.9.0

**Release Date**: Week 6, 20-08-2026 at 14:46
**Version**: 1.9.0 (previously 1.8.0)
**Object**: feat: SCARA workspace envelope, RRF-faithful IK and verified homing + publish-readiness pass
**Code review**: `docs/3-code-review/CR_w6_v1.9.0.md` (Codex loop, 7 rounds -> APPROVED)

## Changes

Two field problems on the lab SCARA drove this release. One turned out to be a board
problem, not a slicer problem; the other was real and is fixed here. A publish-readiness
pass over every user-facing string rides along, ahead of the first public release.

### Workspace envelope (Finding: "only a small area works; outside it the arm lurches")

`RobotLimits` gains `XMin/XMax/YMin/YMax` and `CheckEnvelope`, defaulting to the
machine's real negative-Y half-plane. Previously the validator only knew a 360° reach
annulus, so it happily passed poses the firmware then clipped — producing off-toolpath
motion. `CheckPoint` now enforces the Cartesian box (arcs route through `SampleArc`),
and `FirmwareLimitCheck` was rewritten to signed per-bound comparison against the live
`M208` values, with an `M669` kinematics cross-check.

### RRF-faithful inverse kinematics

`ScaraKinematics` gains `TryResolveTheta` (whole-turn wrap into the `A` limits) and
`InverseRrf` (arm-mode selection matching the firmware's own branch choice).
`RobotChecks.Run`/`RunPoints` became a single ordered stateful walk that threads
`(armMode, thetaTurns)` through every move, segment interior and arc sample, raising
`ProblemKind.ConfigFlip` on a genuine discontinuity — an arm-mode change always, and a
theta wrap only on an exact integer turn-count disagreement, never on the atan2 branch
cut. Session-level `ArmConfiguration` tracks the machine's real configuration; while it
is `Unknown`, configuration-sensitive actions are refused.

**Behaviour change:** jobs that previously validated clean may now report `ConfigFlip`
errors or resolved-angle jerk warnings. These are real problems the old model could not
see.

### Verified homing and `/sys` protection

`Home` no longer reports success on a sent command. It reads the live `homeall.g`,
requires an observed non-idle → Idle transition within the homing timeout, inspects the
firmware reply, and checks per-axis `Homed` flags — failing closed if it cannot confirm.
Per-axis `Hm X/Y/Z` is available behind two-press arming and verifies only the axis
asked for, so isolated bring-up works while other axes are unhomed. An unreadable
`homeall.g` no longer blocks homing: homing is the recovery path, so it proceeds and
reports the configuration as `UNKNOWN`. `xHomed`/`yHomed`/`zHomed` outputs added.

The Files component now refuses to delete or move `0:/sys` and `0:/firmware` paths
unless an explicit maintenance override is armed, checking **both** endpoints of a move.

### Kinematics verification actually works now

Found during code review: kinematics were never verified on this machine, and the gate
that depends on them **refused every upload and print start**. Three compounding causes,
all fixed — the `M669` probe ran only on legacy boards while the gate was unconditional;
`TryParseM669` required an `R` word the board never reports; and an absent `R` was
compared as `0` against `ReachMin`, manufacturing a mismatch. Modern boards now read
`move.kinematics` from the object model, and `R` is optional end-to-end.

### Machine-command authorization

Status transitions are now attributed to a specific submitted motion rather than to
"a command wrapper is running". `MarkInitiatedMotion()` is called immediately before
each accepted motion submission and only there. An external DWC jog, pause or cancel is
therefore recognised as foreign and invalidates the tracked arm configuration — which
matters because `cancel.g` homes and `pause.g` lifts the head. Raw expert Terminal
commands are treated as opaque motion and invalidate rather than authorize.

### Three pre-existing bugs fixed

- **E-stop bricked the jog UI.** `RunEmergencyStop` never cleared `_busy`, so every
  Home and jog button reported "another action is executing" forever afterwards.
- **Validate/Upload froze the canvas.** Full IK validation ran synchronously on the
  Grasshopper UI thread; it now runs on a worker and publishes only if the content hash
  still matches.
- **A stale-snapshot latch disabled buttons.** The poll interval could exceed the
  freshness window; the cap is lowered and a stale → fresh poll forces a relayout.

### Seam placement extracted to Core

`MoverComponent.SetSeam` moved to a pure, Rhino-free `Core/Paths/SeamPlacer.cs`
(`enum SeamMode`, `TargetFor(...)`). Byte-for-byte identical behaviour; the `int` input
is kept so saved definitions still open.

### Publish readiness and component text

- `.claude/` is now git-ignored — it held ~2.9 MB of AI session state in the repo root,
  untracked but **not** ignored, so `git add -A` would have published it.
- The machine serial `SCV4-2373` is **kept** deliberately; the rationale is recorded in
  `docs/dev/RELEASING.md` so it cannot resurface as an oversight.
- Every two-press confirmation now reads as **"double-click … to confirm"** where the
  guard arms synchronously, **"armed — click … again"** once the first click has landed,
  and a distinct sentence for the one site that arms asynchronously. The countdown
  seconds are gone from the UI; the windows themselves are unchanged.
- Corrected user-facing text that was simply wrong: the `PrintStats.timeMin` description
  contradicted its own `accel` input; a tooltip cited `OPEN_QUESTIONS.md`, a file that
  does not exist; seven tooltips told users to type `−1` using a Unicode minus that
  Grasshopper cannot parse. Removed the internal tokens `NEEDS_INPUT`, `arctic`,
  `slicer4rtn` and "the lab bed sweet spot"; unified British/American spelling.
- `elbow` was labelled "preview-only" in six components and in `DUET_CONTROL.md`, but it
  seeds the home-macro replay that establishes the tracked configuration. Descriptions
  corrected; the behaviour change is deliberately deferred.
- `INSTALL.md` now warns that an internalized Duet password is stored inside the `.gh`
  file. `ARCHI.md` corrected: 23 components (not 22), `Duet Live` added to `7 Print`,
  and the two distinct homing boundaries distinguished.

### Field diagnosis: "Home All homes Z only" is a BOARD problem

Confirmed on hardware, no slicer change applies. The Duet was reflashed to stock
RRF 3.5.1 but kept its *3DPotter Edition 3.1.1* config. The arm axes run on external
drivers that stall at the ~44 kHz homing step rate under stock 3.5 timing, so X/Y never
register homed and the absolute park move aborts with "insufficient axes homed".
Lowering the homing feedrate homes X/Y correctly. Fix belongs in the board config
(`M569` timing, lower feedrates, per-axis step-off) or by restoring the matched
firmware. The slicer now surfaces this honestly instead of hiding it.

## Tests

**512 passed / 0 failed** (baseline on `master` was 456). Debug and Release both build
with **0 warnings / 0 errors**. New: `KinematicsVerificationTests`,
`DuetFileProtectionTests`, `SeamPlacerTests`.

**Known gap:** `DuetSession` and `DuetJogComponent` live in the plugin project, which the
Core test suite does not reference, so the homing and authorization fixes are not covered

owed — nothing automated covers Grasshopper tooltips.
