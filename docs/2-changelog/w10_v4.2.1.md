# v4.2.1 - Slicing review fixes: conical adjacency, adaptive gaps, restart frame

Week 10, 2026-09-10. Branch `feature/4.1.0-ldm-bricklayer-wave-infill`.

A read-only review of the 4.1.0 slicing code and of the non-slicing layers found
four confirmed defects. Two were reproduced against the Release Core assembly
before anything was changed. No component contract changes: no socket was added,
removed or reordered, so every 4.1.0 / 4.2.0 document loads unchanged.

Reviews: [slicing](../dev/CODE-REVIEW-SLICING_2026-09-10.md) ·
[repository](../dev/CODE-REVIEW-REPO_2026-09-10.md).

---

## 1. Bricklayer did nothing on conical walls

`LayerBuilder.BuildConicalTagged` maps its walls back onto the conical surface
before Bricklayer sees them, so a "flat" conical layer has a Z that varies with
radius. Bricklayer's adjacency test claimed to measure XY distance but ran the
3-D `SegmentGrid.Nearest` on that mapped geometry: two walls one bead width `w`
apart radially on a cone of angle `a` are `w / cos(a)` apart in 3-D, and the gate
is widened by only `1e-9`. Every material cone angle therefore failed the gate.

The feature reported as enabled and shifted **zero** paths. Reproduced: two
concentric rings at 30° with 2 mm radial spacing and a 2 mm gate gave
`PathsShifted=0`.

Adjacency is now built on an XY projection of the wall points, leaving the
global 3-D `SegmentGrid` contract alone. Contour lengths - which pick the
shorter loop for the overlap test - are measured on the same projection, so the
choice no longer depends on the cone angle either.

## 2. Adaptive layers defeated both safety arguments

The adaptive stack was handed to both passes with the *nominal* `layerHeight`.

**Non-planar** bounded its amplitude at `MaxStepFraction * LayerHeight` and never
looked at the actual `LayerPaths.Level` values. With a 3 mm nominal height and
`hMin = 0.2 mm`, an amplitude of up to 1.2 mm passed the check while sitting on a
0.2 mm gap. Reproduced: two layers 0.2 mm apart with amplitude 1 and a half-turn
phase gave `lowerZ = 1.000`, `upperZ = -0.800` - the layers had swapped order.
The limit is now the minimum over every adjacent pair of
`2 * MaxStepFraction * gap / (ramp(i) + ramp(i+1))`, which is the real crossing
condition: two unit profiles a half turn apart differ by up to `2 x amplitude`,
and each end of the pair carries its own ramp factor. A single-layer or entirely
flat-ramped stack keeps the documented nominal bound.

**Bricklayer** computed one global `dz = ShiftFraction * LayerHeight` and applied
it to every layer, so on a nonuniform schedule the intended half-layer running
bond became an unrelated fixed lift that could move a wall onto its neighbour.
Each layer now lifts by its own upward level gap; the last layer reuses the
previous gap and a single-layer stack keeps the nominal height. Non-increasing
or non-finite levels are rejected in both passes rather than silently mis-shifted.
The Slice component's warning line says "x each local layer gap" when adaptive is
on, because the millimetre figure it used to print is no longer one number.

## 3. Two hardening fixes

- `Bricklayer.Apply` validates `ShiftFraction` (finite, `[0, 1]`) like it already
  validated the height, bead width and overlap. NaN previously produced `Z + NaN`
  vertices that escaped into downstream consumers.
- `Infill.ZigzagSpans` / `WaveSpans` skipped null rings while deciding whether any
  usable ring existed, then dereferenced every ring in the rotation loop. A list
  with one valid and one null ring passed validation and threw. Both now skip
  null and degenerate rings consistently. Core callers only; `LayerBuilder`
  supplies cleaned rings.

## 4. G-code Restart's point was documented in the wrong frame

`GcodeRestartComponent` converts `point` from document units to mm and then
through `MachineFrame.ToMachine`, i.e. it expects a **Rhino/document** point.
The socket description, the class summary and the wiki all told the user to read
the machine XYZ off the Duet and type that in - which applies the reflection a
second time and can cut the restart at the wrong location on a print that has
already failed once.

The three surfaces now agree on the Rhino/document contract, and the wiki records
the conversion for someone holding raw Duet numbers: Duet `(200, -500, 400)` is
Rhino `(500, -200, 400)` mm. **The parameter itself is unchanged** - same name,
nickname, order and type - so archives and existing wires are unaffected, and a
wire from a Live View or Console position output was always correct.

No automated regression was added: the test projects reference Core and cannot
instantiate a Grasshopper component, so a Core-only assertion would merely
restate the existing `MachineFrame` tests. Package validation should use a
non-symmetric point in a non-millimetre document.

## 5. The release script hid its own diagnostics

`tools/release.ps1` piped `dotnet clean/build/test` to `Out-Null` and reported
only `Release build failed`. In the 4.2.0 candidate run the solution restore
failed while a per-project restore succeeded, and the script produced no
actionable text - the Yak had to be staged by hand from a successful Release
build. Each dotnet invocation now runs through one helper that keeps the merged
output and prints it before failing. The zero-warning gate is unchanged but now
names the warnings it rejected.

The script also stages `INSTALL.md` and `UPGRADE.md` into
`dist/send-IAMLabSlicer-<version>.zip`. They were dropped when packaging was
automated in 2.6.0, so every send zip since shipped a `.yak` with no instructions
next to it. They go into the zip, not the stage, so the `.yak` payload and its
extension allowlist are untouched.

## 6. Verification

| Gate | Result |
|---|---|
| `dotnet build IAMLabSlicer.sln -c Release` | clean, 0 warnings |
| Core (`net10.0`) | **1711 passed** (1706 + 5 new) |
| FrameworkSmoke | **418 passed** on each of net48 / net7.0 / net7.0-windows |
| `tools/release.ps1` (candidate) | passed end to end, `.yak` built by Yak.exe |

The five new tests reproduce all four faults: conical adjacency shifting an inner
wall, unequal adaptive gaps with the last-layer fallback, an adaptive gap that
must refuse an amplitude the old check accepted, a flat end ramp that must *not*
be refused, and null/degenerate rings through both infill patterns. Two xUnit
analyzer warnings in the touched wave/non-planar tests were corrected.

### Owed

- **Nothing has been printed.** All four fixes are covered by Core tests only;
  no conical bricklayer wall and no adaptive non-planar stack has been sliced in
  Rhino, let alone extruded.
- The restart component's input contract has no component-boundary regression;
  it needs the manual non-symmetric-point check in a non-millimetre document.
- The 4.2.0 icon still comes from the Pillow fallback rather than
  `make_icons.ps1`, which needs a machine with working headless Edge.
