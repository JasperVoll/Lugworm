## 1. Every wall and every infill now starts at a geometric seam

With one wall - the usual clay setting - the infill was anchored at the section
perimeter's end vertex, which `Rdp.Simplify` places at the vertex farthest from the
centroid: on a round section a coin toss per layer (probe: -134, 99, 4.5, -91, 17, 52,
154, 178 deg over eight layers). The spiral start and the Fermat corridor followed it, so
the whole pattern rotated at random from layer to layer; zigzag and wave chose their first
row direction against the same vertex.

- `Core/Paths/SeamAnchor.cs` (new): exact ray-ring intersection (farthest hit on a concave
  ring), closest point on a ring's segments, `SplitAt` (re-start a ring at an inserted
  point), area centroid.
- `LayerBuilder` re-starts every closed wall - the section ring and every offset - where
  the +X ray from its own area centroid crosses it, so the last wall's end is a continuous,
  vertex-independent anchor for every infill mode.
- `Spiral.Inward`, `Fermat.OpenAtSeam`, `Chain` and `Helix` chain rings by exact projected
  split points instead of nearest vertices.
- Spiral and Fermat report their fall-back to independent rings (`rings not strictly nested
  (n islands at depth k)`) through `LayerPaths.Diagnostic`; Slice puts it in `info` once
  per object. Before, the fall-back was silent.
- Regression: a 12-layer round stack with a random start vertex, 0.01 mm radial jitter and
  RDP tol 0.1, one and two walls, planar and conical, infill modes 1 to 5 - wall seam and
  infill start spread below 0.5 deg (was up to 360 deg).

## 2. IAMLab Place orients open curves before it seams the walls

Align, Stagger, Guide and Track never touched open curves; Nearest chose an open curve's
start by "which end is closer to the nearest wall", a sub-millimetre tie for zigzag, wave
and Fermat that flipped per layer, and with a `seamPoint` could reverse a spiral into an
outward one starting at its centre.

- `SeamPlacer.OrientOpenPath` (Core, tested): an end far from every wall (twice the other
  end's distance and beyond a bead) never starts; between two wall-side ends the one nearer
  the layer's seam target starts; a near-tie follows the same curve's start on the layer
  below; the first layer falls back to the smaller polar angle from +X.
- The layer's seam target is computed first per mode (Align/Stagger ray, Guide closest
  point, Track previous outer seam, Nearest the point). In Nearest every closed wall then
  seams next to the first open curve's start (one primary start per layer). Keep leaves
  open curves alone. `info` reports `open flipped: n/m`.

## 3. Zigzag and wave infill are one polyline per layer again

Found by the new regression, pre-existing: Clipper rounds row ends to its 0.1 um grid, so
on every curved or oblique boundary the connector to the next row started a hair outside
the edge it sat on, and `Infill.ConnectorInside`'s parametric 1e-6 crossing test called
that a proper crossing. A circle's zigzag came out as 22 polylines for 23 rows, a square
filled at 30 deg as 14 - one travel per row on the printer. A crossing now needs both
connector ends beyond a 1e-3 mm penetration tolerance on opposite sides of the edge line.
Holes still split the fill (`ZigzagConnectorToleranceTests`).

## 4. Non-planar wall waves (clean-room, GPL-3.0 prior art credited)

The infill half of the reference family's non-planar behaviour existed since 4.1.0. The
missing half is the wall modulation with a per-loop phase alternation, the part that
interlocks adjacent loops. Three sockets appended to the `nonplanar` group: `npWallAmp`
(0 = off), `npLoopPhase` (turns per loop, default a quarter), `npWallOuter` (include the
visible wall, default off, mirroring `brickOuter`).

- Phase is a function of planar position, as for the infill, plus `LoopPhaseTurns x
  WallIndex`, so crests of adjacent loops stay spatially aligned and every loop closes
  exactly after resampling.
- Amplitude guard: the same ramp-aware layer-gap rule as `npAmp`, but on the real per-loop
  gap. `Bricklayer.Apply` now records the shift it applied on each path
  (`TaggedPath.ZShift`); at a bricklayer ramp boundary, where a loop goes from flat to
  shifted, the wall limit is 0.4 x half a layer. Refused with a message naming the limit,
  never clamped. (The Codex review caught the ramp boundary; the plan's `A_wall + shift`
  form would have refused every wall wave with bricklayer on and was dropped.)
- Written from a behaviour specification only; no reference code was opened during
  implementation. `THIRD-PARTY-NOTICES.md` extended.
