## 1. DoE - the top three from `proposal_2026-08-31_doe-extensions.md`

- **Inference pack** (`Core/Doe/RsmInference.cs`): 95 % prediction/confidence
  intervals (the fitter now stores `(XᵀX)⁻¹`, serialized additively into the model
  JSON - pre-2.3.0 JSON still parses, its intervals just report unavailable),
  leverage + studentized residuals + Cook's distance per run, VIF per term.
  RSM Evaluate appends a `diag` output and warns on Cook's D > 1 / VIF > 10;
  Desirability appends an `interval` output and marks alternatives whose predictions
  sit inside the recommendation's 95 % PI as `≈best` - D = 0.81 vs 0.79 is no longer
  reported as a ranking. Definitions from Cook 1977 / Marquardt 1970; hand-derived
  fixtures in `RsmInferenceTests`.
- **Pareto front** (`Core/Doe/ParetoFront.cs`): non-dominated sorting + crowding
  thinning (Deb et al. 2002, written from the definitions) over the individual
  desirabilities of the active goals - the d≤0 short-circuit deliberately does not
  apply while collecting, because a d=0 recipe can be best-in-class on another
  objective and those are exactly what the scalarised D hides. Desirability gains a
  `pareto` feature group (off by default; solve cost unchanged when off), an appended
  `pareto` tree output, a front section in the report, and a 2-objective scatter with
  the D-optimum ringed (3+ objectives: a note, never a lying 2D projection). The
  `alternatives` output is now labelled as what it always was: local optima of the
  scalarised D, not a Pareto set. Streaming archive with extreme-preserving interim
  thinning keeps the anti-correlated worst case (every grid point non-dominated)
  inside the perf budget - pinned by a perf-trait test.
- **Monte-Carlo power** (`Core/Doe/PowerAnalysis.cs`): DoE Design gains a `power`
  group (sigma, per-factor effect, model, sims) and a `power` output - "can this
  15-run plan detect a 0.3 mm effect" answered before the clay is mixed, with a
  warning under the conventional 0.8. Simulation refits with the SHIPPED fitter, so
  aliased-term dropping on DSD/Taguchi is reflected honestly (method as in skpr,
  Morgan-Wall & Khoury JSS 2021 - cited, not ported; skpr is GPL).

## 2. One plot system

`Ui/IamPlot.cs` is now the single source of palette, type scale, axis/tick/legend/bar
primitives and colormaps for every on-canvas DoE panel; `GraphRenderer` (effect bars,
contours, desirability profile, new front scatter) is rebuilt on it. Theme-aware:
colours resolve against the Grasshopper canvas skin, so panels are legible on dark
canvases, and the attributes' panel mat/frame follows the same theme instead of
flashing white. Contour min/max labels now use the colormap's own end colours;
effect-bar significance carries a legend.

## 3. Goal-curve editor - PROTOTYPE

A Graph-Mapper-style strip below the Desirability profile: drag the ramp ends, the
target, or the shape handle instead of typing `target=7 in 6..8 s=2`. Edits are
stored as per-response overrides of the wired goal text (never modifying it),
survive save/reopen, are announced as a Remark each solve, and reset with ✕.
Known prototype limits: no undo (use ✕), weight stays text-only, the strip appears
after the first solve. Feasibility verdict + costs:
`docs/6-memo/feasibility_2026-08-31_graph-mapper.md`.

## 4. Maintainer answers applied

- **Per-axis `G28 X/Y/Z` split by kinematics**: `GcodeParser.Parse` gains
  `allowPerAxisHome` (default false - every SCARA path unchanged and pinned).
  Cartesian profiles route it through JobGate, Robot Simulation, Duet Live and Print
  Stats; bare-letter RRF grammar ("G28 X") is normalized to the lexer's strict form
  on G28 lines only. A per-axis home marks `HasPartialHome` and clears the pose -
  the parser still cannot know the post-home position offline.
- **zOffset**: confirmed intentional and documented in ARCHI §11 - only Slicer and
  Place introduce Z by design (one global edit point each); no other component adds
  an offset of its own.
- **Machine-profile plan**: retargeted (version label dropped, `RobotCatalog` +
  `DUET_CONTROL.md` step 12 added as absorption sites, behaviour-identical
  constraint recorded). Not implemented - unchanged behaviour, plan doc only.
- **Cosmetics**: dead `#if false` jog block removed; dead `_tcpWire`/`_printedWire`
  stores removed from Robot Simulation; "M669 kinematics: unverified" session-info
  noise suppressed for Cartesian profiles; Duet Live shows a neutral origin-centred
  plate for Cartesian profiles instead of the Potterbot plate.
