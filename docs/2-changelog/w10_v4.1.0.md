# v4.1.0 - LDM-only retrenchment, Bricklayer walls, non-planar and wave infill

Week 10, 2026-09-09. Branch `feature/4.1.0-ldm-bricklayer-wave-infill`
(`6e1be2f` → `362a052` + this release commit).

Version 4.1.0, not 5.0.0, although sockets, an output and two robot profiles are
deleted: **4.0.0 was never published**, so nothing removed here ever shipped. The
removals are still declared explicitly against the v3 contract baseline rather
than hidden (§21 of ARCHI.md).

## 1. The machine is LDM-only again

4.0.0 added a second extrusion model, a sixth console tab, a second transport and
a temperature-history subsystem for a machine class this lab does not run. ARCHI
§24 already listed the sharpest consequence: **Klipper through Moonraker had never
been connected to a real printer**, and the thermals UI had never been drawn in
Rhino. Rather than carry ~1,500 lines of unverifiable transport plus a whole
extrusion model that served no machine, 4.1.0 removes them.

### Removed

- **The filament (thermoplastic) extrusion model.** `FilamentExtrusion`, the 12
  filament fields on `GcodeConfig`, the builder's five `Thermoplastic` branches,
  the header's heat-and-wait block and cooldown footer, the restart path's
  re-heat preamble, the G-code component's whole `fdm` group (13 inputs) and its
  `filamentMm` output.
- **The console's Thermals surface.** `ThermalsPage`, `MachineConsoleForm.Thermals`,
  `ThermalCommands`, `ThermalHistory`, `DuetThermals`, the Thermals tab, the
  Dashboard heater strip, the `thermal:*` action dispatcher, the
  `heat`/`fan`/`extrude`/`tune` gates and the five heater/fan outputs.
- **The direct Klipper connection.** `Core/Klipper/` in full (`MoonrakerClient`,
  `KlipperStatus`, `MoonrakerClientOptions`), `RobotControlKind.Moonraker`, the
  `Thermals`/`PressureAdvance` capability flags, and the robot profiles
  `generic-klipper-fdm` and `generic-marlin-fdm`.

### Kept deliberately

- **Every G-code dialect, Klipper included.** `GcodeFlavor.Klipper`,
  `Core/Gcode/KlipperCommands.cs`, `KlipperCommandsTests` and the fail-closed job
  parser's acceptance of the three extended commands the generator emits are
  untouched. A Klipper board driving a ram or pump extruder is still a supported
  *target*; it receives its job as a file. `generic-klipper` stays as a
  dialect-only profile and a new `generic-marlin` replaces the FDM Marlin entry.
- **`speedFactor` and `flowFactor`.** M220/M221 overrides are not thermals.
  `ThermalSnapshot` was *reduced* to `MachineOverrides` rather than deleted, and
  the persisted output-category id stayed the literal string `outTemperatures`,
  so a saved document keeps its output-toggle state. The UI label changed; the
  contract string deliberately did not.
- **The Robot Definition's `process` socket**, now always reporting
  `Paste (LDM)`. A socket is a saved-document contract; the enum behind it is not.
- **The transport seam** (`IMachineClient`). It is what keeps the safety gates
  independent of any one client, and re-adding a transport is a factory case
  rather than a rewrite.

### The proof this changed no paste G-code

`GcodeBuilderTests.RamOutput_MatchesV4Baseline` pins the ram output byte for
byte. The baseline was salvaged out of `FilamentGcodeTests` **before** anything
was deleted, and then verified by running it in a detached worktree at the
pre-removal commit, where it also passes. That makes "the removals are a no-op
for paste G-code" a measurement rather than a hope.

## 2. Layer paths carry roles

`Core/Slicing/LayerPaths.cs`: `LayerBuilder.BuildTagged` / `BuildConicalTagged`
return a `LayerPaths` whose every `TaggedPath` says what it is - `Wall` (with its
index, 0 = outermost), `Infill`, or `OpenSection`. The pre-4.1.0 `Build` /
`BuildConical` delegate to them and flatten, so **no caller and no test changed**.
The Slice component keeps the tagged stack until the output boundary, which is
what lets the two new passes act on the right paths and see every layer at once.

## 3. Bricklayer walls

`Core/Slicing/Bricklayer.cs`. Within a layer, adjacent wall loops are two-coloured
and every other colour rises by half a layer height, turning the vertical seam
between two bead columns into a running bond.

- **Both adjacency gates are required**: XY distance within one bead width **and**
  more than 50% of the shorter loop running that close. The distance gate alone
  bonds rings that merely touch at a tangent point; the overlap gate alone bonds
  rings on opposite sides of the part.
- **A non-bipartite component shifts nothing.** Three mutually adjacent loops form
  an odd cycle, and any two-colouring of it would put two shifted loops side by
  side. The component is left flat and named in the report.
- The outermost wall stays flat unless `brickOuter`; `brickRamp` layers stay flat
  at the bottom and top.

**Conical layers need no separate path**, and the obvious design is wrong: the
inverse conical map subtracts a function of the radius only and leaves XY
untouched, and the chord refinement is radius-driven too, so raising a contour in
the sheared frame and raising it after the map give identical points. One uniform
pass serves both slice modes; `ConicalShift_EqualsShearedFrameShift` pins the
equivalence rather than leaving it as a comment. This is a documented deviation
from the plan, which had asked for a sheared-frame shift.

**Known limitation, stated in the component:** the pass emits geometry, not
extrusion. A shifted loop's gap to the layer below is 1.5x the layer height on the
ramp-in layer and 0.5x on the ramp-out layer. The answer is the G-code
generator's existing `varh` group, and the component emits a remark saying so
whenever it shifts anything. No flow factor was invented here.

## 4. Non-planar infill

`Core/Slicing/NonPlanarInfill.cs`. Infill paths - only `Infill`-tagged ones - are
resampled and their Z displaced by a periodic profile along one direction, with a
per-layer phase advance (0.5 turns puts the next layer's trough over this layer's
crest). The amplitude ramps in over the first N layers and out over the last N,
because this slicer has **no solid top/bottom layers** to taper against; the first
and last layer stay exactly flat. An amplitude above `MaxStepFraction` x the layer
height is **refused with an explicit error, never silently clamped**.

**No per-segment extrusion correction is applied, deliberately.** `GcodeBuilder`
measures every segment with the 3-D `PolylineOps.Dist`, so E already scales with
the tilted length; the correction factor the reference post-processor applies
would double-count here.

## 5. Wave infill and the Graph Mapper wire

`Infill.WaveSpans`, infill modes **5** (sine) and **6** (graph), appended so a
saved `infill = 3` still means Spiral. Parallel rows follow a periodic profile
instead of running straight, **mirrored row to row** so one row's crests face the
next row's troughs. `waveTangent` makes the mirrored peaks meet exactly;
otherwise they stop `waveClearance` short. Row pitch, boustrophedon connection,
the hole/concavity connector guard and the wall anchor are `ZigzagSpans`' own.

Amplitude is enforced **strictly below spacing/2** - not cosmetically, but because
the single Clipper run recovers each clipped piece's row from its own y, which is
unambiguous only while every point stays inside its row band.

`IAMLab Graph Mapper` gains a fourth output, **`map`** (appended), carrying
`GraphMap.Serialize()`. Slice's new `profile` input deserializes it, so the curve
crosses as a *function* and the infill resolution stays the slicer's decision
instead of being fixed by whatever sample count a wire happened to carry.
`GraphProfile` ping-pongs by default so any curve tiles continuously even when
`f(0) != f(1)`; `repeat` plays it forward and the component warns when the ends
then disagree.

**Prior art, and the licence line.** The interlocking-wall and wave-infill ideas
come from Roman Tenger's and GeekDetour's **GPL-3.0** BrickLayers post-processing
scripts. This plug-in is MIT. Their published behaviour was read as a
specification and reimplemented from scratch against this project's own geometry
model; **no code, comment, string or data file from either project was copied,
vendored or ported.** See `THIRD-PARTY-NOTICES.md`.

### Two defects worth recording

Running the Rhino contract gate for the **first time ever** immediately showed the
gate itself was broken: `verify-component-contracts.py` invoked
`SyncInputs(bool recordUndo = true, bool recompute = true)` by reflection with no
arguments, and reflection does not fill optional parameters
(`Parameter count mismatch`). The defect is older than the v3 baseline - the
signature has had its optional parameters since 2026-06-24 - and had simply never
been exercised, because the probe had never been run. Fixed here, out of this
release's scope, by passing both arguments explicitly as `False`: also more correct
than the defaults, since this probe records no undo events and must never solve.

During implementation the bricklayer adjacency gate silently matched nothing on
the commonest input of all - two walls offset by exactly one bead, which is what
`wallCount > 1` produces every time. `SegmentGrid.Nearest` only accepts a
candidate *strictly* closer than its distance cap, so querying at exactly
`beadWidth` rejected it. Five tests failed on that one root cause. It was caught
by a test, not by reading the code.

### What is owed

- **Nothing in this release has been printed.** The three new groups are covered
  by Core tests only; no shifted wall has been drawn in a Rhino viewport and no
  wave infill has been through the G-code generator on hardware.
- `varh` over wave-modulated infill is an approximation:
  `VariableFlow.LocalHeights` falls back to its nearest-segment metric on a
  branch that is no longer horizontal. The error is unquantified.
- The adjacency test's cost on a real multi-island part is unmeasured; the
  per-layer pair budget is a guard, not a benchmark.
- The **contract baseline capture is still owed**. The *comparison* now runs and
  passes against v3 with 4.1.0's and 4.0.0's breaks declared, but a capture must
  follow the manual Rhino round, which has not happened.
- The three offline solving probes (`calibration-units`, `pareto-selection`,
  `interlayer-time`) have still never been executed.
- The Potterbot 4.0.0 regression is still owed.
