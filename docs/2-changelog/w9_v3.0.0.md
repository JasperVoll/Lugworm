## 1. One control surface

The **7 Print** group goes from 10 components to 5. `IAMLab Duet Print Console` is renamed
**IAMLab Duet Console** (GUID `…0029`, unchanged) and absorbs connection, homing, jogging,
origin capture, job control, terminal and go-to into one window.

**Duet Connect, Status, Jog, Terminal and Print become hidden compatibility components**
(`GH_Exposure.hidden`). Their GUIDs, sockets, gates and persistence are byte-identical -
they are off the ribbon, not gone, and old definitions keep working unchanged.

Remaining on the ribbon: **Duet Console, Files, Duet Live, Calib Points, Scara Fit**.

## 2. Sockets

- **Outputs are append-only.** Indices 0-7 (`status`, `state`, `progress`, `pos`, `homed`,
  `jobFile`, `log`, `info`) keep their positions, so output wires on a 2.6.0 console
  survive. Twelve new outputs follow: `host`, `connected`, `reply`, `xHomed`, `yHomed`,
  `zHomed`, `bedOrigin`, `zZero`, `uploaded`, `danger`, `problems`, `messages`.
  New definitions wire Files / Live / Calib / Scara Fit from the console's `host` exactly
  as they wired from Connect.
- **Inputs gain** `pollMs` (from Connect), `dryRun` / `arcSupport` / `blockWarnings` (from
  Print), the limits group **once** (from Jog and Print), and `feed` (from Jog).
- **`open` is removed** - the window opens from a **Console** capsule on the component, and
  a second press fronts it. Removing an input shifts the ones after it, so Grasshopper
  remaps the remaining input wires by position: **re-check the console's input wires once**
  after upgrading. The 2.6.0 "reopen on load when saved open" behaviour is gone.
- **`expert` and `line` are removed** from the terminal. Opening the Terminal tab is itself
  the expert act; a separate unlock added a step without adding a decision. The allowlist
  and the two-press confirmation - the parts that actually gate - are unchanged.

## 3. The window

Rendered with SkiaSharp as a drawn control tree: a header (connection, board, machine
state, arm configuration, per-axis homed lamps, job progress, machine-frame position), a
tab strip, and **Control / Job / Terminal / Log** tabs.

- **E-STOP and Reset are native WinForms buttons** docked outside the drawing surface.
  Skia is deliberately not treated as a resilience boundary: a missing or mismatched
  native kills the CPU and OpenGL surfaces alike, so the two controls that must work when
  everything else is broken are never drawn by it. If Skia cannot paint at all, the window
  says so and those buttons still work.
- **CPU raster is the default; OpenGL is an opt-in** on the component's context menu.
  In-process GL inside Rhino could not be verified during the spike, so it stays opt-in
  with a guarded first paint that falls back to CPU by itself.
- **Every disabled control shows its refusal reason inline**, beside or beneath itself
  rather than in a tooltip alone - and the strings come from the same gate the canvas
  capsules use, so the window and the canvas cannot disagree.

## 4. Safety

Every gate is the one that was already there, reached through the same call chains. Two
rules are deliberately **stricter** than what they replace, and one gap is closed:

- **Reset (M999) from the console requires Halted/Off.** The Jog capsule's armed any-state
  override is not carried into the console; it survives on the hidden Jog component. A
  console-entered `M999` in the Terminal tab takes the same predicate, so the tab is not a
  bypass around the button. Accepted consequence: recovering a wedged-but-not-halted board
  from the console needs E-STOP first (which halts it), or the hidden Jog component.
- **The window can no longer offer what the transaction would refuse.** The button gate now
  consumes the session's trust refusal, the home-macro probe, the unresolved control
  profile and the fail-closed Cartesian envelope list - all of which refuse inside
  `RunGatedCommandAsync`. The homing predicate is unchanged and remains the right one:
  refuse only when the macro probe **completed** and the axis has no macro, because homing
  is the recovery path out of an unknown configuration.
- **The motion-limit `warned` flag is no longer dropped.** Upload and Start discarded it
  (`var (notice, _)`), so a successful-but-warned run rendered as a plain remark; it now
  reaches the state and the status line.

## 5. Press-and-hold jogging

The jog pad repeats while held, with **at most one jog in flight, ever** and queue depth
structurally zero (`Core/Duet/JogRepeatPolicy.cs`, tested). The next step is released only
after the previous gated transaction completed **and** a poll cycle that *started* after
that completion produced a snapshot - the transaction's own pre-send snapshot does not
count, because the poll loop and the command path fetch snapshots independently. The
acknowledgement is a monotonic poll **generation**, not a timestamp.

A `Busy` acknowledgement waits rather than ending the hold, since the planner gates on Idle
and a long step is still executing when that poll lands. Any refusal ends the repeat instead
of retrying into a closed gate. An auto-repeat can never arm or consume the paused-jog
maintenance override - that override is armed as a side effect of the refusal itself, so the
right is withheld before the send rather than after the refusal returns.

## 6. Latency

- `DuetSession.RequestPollSoon()` shortens the current cadence wait after an **accepted**
  command, so the effect of an action reaches the UI on the next poll instead of up to a
  full interval later. It uses a dedicated wake semaphore that only the healthy-cadence
  wait observes: the poll loop treats a cancelled delay as shutdown, so sharing the session
  token would turn every "poll now" into a disconnect and strip the reconnect backoff.
- A **focused** console window raises the poll rate to 250 ms while the machine is active.
  Focus registration is owner-keyed, so two consoles on one host cannot blur each other's
  cadence off.
- Neither path adds a send, and the canvas expire policy is untouched.

## 7. Behaviour change worth knowing

`reply` became output 10, so a firmware reply now participates in output equality and can
expire the canvas - throttled to at most one re-solve per second, and never while `live` is
off. In 2.6.0 replies reached the canvas only through `log`. The test that asserted replies
never expire was updated rather than preserved, and a new test pins the throttled
reply-triggered expiry.

## 8. Packaging

SkiaSharp and OpenTK (all MIT) join the package, **exact-pinned to 2.88.6**. Rhino ships no
SkiaSharp but other Grasshopper plugins do, and every 2.88.x build carries managed identity
`2.88.0.0`, so in Grasshopper's shared load context the first plugin loaded wins for
everyone; matching the version already in the ecosystem keeps that coexistence benign in
either load order. These versions must not float.

The native placement is asymmetric by target and both halves are load-bearing: `net48`'s
loader probes `x64\` beside the managed assembly, while the netcore folders need the native
at the assembly **root** - with the usual `runtimes/` layout the process loaded a *wrong*
`libSkiaSharp.dll` from Git's `mingw64\bin` off `PATH`. `tools/release.ps1` now stages the
Skia payload and **asserts** that layout survives staging; its allowlist would otherwise
have silently shipped a console that cannot paint.
