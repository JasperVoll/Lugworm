## Changes

Duet Live can now record what the machine actually did, not just draw it. With the new
`log` feature group armed, every status poll is turned into a timestamped record of the
real nozzle path carrying the firmware layer number, print speed and cumulative
extrusion. Records land at layer start/end plus every Nth poll, and stream to CSV as the
print runs.

The motivating use is interlayer adhesion: knowing exactly when each layer was printed,
and how fast, so a later analysis can correlate bond strength with the time gap between
layers. That analysis is explicitly **not** part of this release — this produces the
record it needs.

### Why the recorder sits in the poll loop

The old `_trail` in Duet Live sampled inside `Compute`, driven by session-change events
that are deliberately coalesced: whenever the canvas was busy, polls were silently
dropped. That is survivable for a decorative trail and disqualifying for a measurement.
The recorder now rides the poll loop itself, so no snapshot is missed, and the decision
logic lives in Core where the xUnit suite reaches it.

### What the log records

New Core module: `PrintLogRecord`, `PrintLogRecorder`, `PrintLogCsvWriter`, `PrintLogSink`.

- **Run identity is the printing-state transition, not the file name.** The first
  printing snapshot often carries no job fragment at all, and the legacy API deliberately
  nulls the file name when `rr_fileinfo` fails, so keying on the name would split ordinary
  jobs. The name is adopted instead: first non-empty value wins, empties are ignored, and
  only two differing non-empty names split a run.
- **Layer boundaries are fully defined**, including the first and last. The first
  `LayerStart` is deferred until the layer is known (or opened immediately in Z-step mode,
  since the first physical layer never produces a rise); the final `LayerEnd` is emitted
  even when a run is cut short, with the span marked incomplete.
- **Both speed sources.** Firmware `speeds.requested`/`top` (instantaneous at poll time)
  and a derived `|Δpos|/Δt` (the true poll-window average). They answer different
  questions, and their disagreement is itself informative.
- **Honest uncertainty.** Every boundary record carries `boundary_uncertainty_s` — the gap
  between the two snapshots bracketing it. A log-side finish reports the real elapsed gap,
  never a fabricated zero.
- **23 CSV columns**, invariant-culture, one file per run, streamed as the print proceeds.

### Snapshot telemetry that was being thrown away

The legacy `rr_status?type=3` response already carried `speeds.requested`, `speeds.top`,
`params.speedFactor` and `filePosition`; the parser discarded all of it. Now parsed, along
with `extrRaw` (the *raw* extrusion total — not `coords.extr`, which has the extrusion
factor applied and would mean something different on each board). RRF3 boards additionally
fetch `move.currentMove` and `move.speedFactor`, each individually failure-tolerant, and
the speed factor is normalized to percent because RRF3 reports a fraction where the legacy
API reports a percentage.

Status columns carry the *parsed* state name on every board: the legacy API reports
protocol letters (`P`, `I`) and RRF3 reports words, so a raw value would make any CSV
filter board-dependent.

### Disk I/O cannot stall the machine session

`PrintLogSink` owns a background thread and a bounded queue; the poll loop only enqueues.
A file write has no timeout, and the poll loop is what keeps the Duet session alive and
`StateGate` snapshots fresh — so a log folder on a disconnected network share would
otherwise have taken machine control down with it. When the sink cannot keep up it drops
and counts rows rather than pushing back, and the component says so plainly: the CSV is
complete only while `rows dropped: 0`.

### Also

- `ObjectModelDiff` extracted from `DuetSession` into Core, so the property this feature
  must not break — motion telemetry stays out of change detection, or the canvas returns to
  the 1.7.0 redraw storm — is now unit-testable rather than a convention.
- Owner-keyed log registration: the session is shared per host, so the earliest enabling
  Duet Live owns the settings and later ones report `Secondary`. One machine, one log.
- `SessionChangeKind.PrintLog` (16) added; `All` deliberately stays 15 so no existing
  subscriber gains expires.

### Known limitations (documented, not hidden)

- **On RRF < 3.2 — which is this lab's Potterbot — a cancelled run cannot be told from a
  clean one by state alone.** The legacy API has no cancelling state, so an operator cancel
  lands on `Idle`. Use `fraction_printed < 1` on the run-end rows.
- Layer timestamps are accurate to ±1 poll (~1 s). This is not a hardware trigger.
- The Rhino 8 smoke test could not be run in the release session; a 12-row on-machine
  protocol is in `docs/dev/TESTING.md`.
- New `docs/4-unit-tests/COVERAGE-DEBT.md` records the sink's queue-drop path (no
  deterministic seam to stall the consumer) and the pre-existing plugin-assembly gaps.
