# Changelog - Week 8, 01-09-2026, V. 2.6.0

**Release Date**: Week 8, 01-09-2026
**Version**: 2.6.0 (previously 2.5.0)
**Object**: fix/feat: release-readiness hardening - units, culture, Duet transport & identity trust, async file I/O, reproducible packaging, IAMLab Version component

> Implements the approved findings of `docs/3-code-review/AUDIT_2026-09-01_release-readiness.md`
> (spec: `docs/superpowers/specs/2026-09-01-iamlabslicer-release-readiness-fixes-design.md`).
> Behaviour-preserving for valid inputs on millimetre documents; every observable change
> below was individually approved. AUD-SEC-001 (password in the .gh) is accepted policy
> and unchanged.

## 1. Correctness & units

- **Document-unit adapter (AUD-COR-001)**: Core stays millimetre-only; `DocUnits`
  converts geometry in (duplicated copies) and previews/outputs back out at every
  component boundary. mm-labelled inputs stay physical mm; G-code/Duet stay mm;
  mm documents are byte-identical (scale 1 short-circuits). SolveCache identities carry
  the unit scale. Hidden legacy robot viewers deliberately stay mm-native.
- **Sample/point alignment (AUD-COR-002)**: dropped non-finite/duplicate contour points
  now take their same-index flow/height samples with them - per-segment extrusion no
  longer silently degrades to a mean poisoned by removed points.
- **Finite-input validation (AUD-COR-003)**: `VariableFlow`/`SlopeFlow` reject NaN,
  infinities, non-positive multipliers and reversed height clamps at the Core entry (a
  negative multiplier could command reverse extrusion); `GcodeBuilder` also validates
  every supplied flow/height sample before emission. The component surfaces them as
  runtime errors.
- **Debug-pass boundary fixes**: Robot Simulation's bed curve now joins its other geometry
  outputs in document units, and non-finite `robot.xml` values can no longer become trusted
  limits or a calibrated home pose on modern .NET.

## 2. Culture & CSV

- **Invariant machine text (AUD-CULT-001)**: every remaining current-culture
  interpolation in G-code, restart and the XLSX shared-string parse is wrapped
  invariant. New `CultureInvarianceTests` fixture runs Marlin/RRF/restart/Duet
  JSON under de-DE and asserts identical output (AUD-TEST-001).
- **File-level CSV format detection**: RSM tables and pump calibrations are English,
  German or neutral per FILE; mixed conventions, thousands separators and
  comma-shredded German decimals ("1,5,2,5") raise a `CsvFormatException` naming the
  line instead of silently wrong numbers. Malformed quoting and exponent overflow are
  refused too. Independent of the Windows culture.

## 3. Duet transport & machine trust

- **Bounded streaming (AUD-SAF-001/002)**: headers-first responses, the 4 MiB cap
  enforced during the read, download bodies and writes under the transfer timeout,
  bounded teardown waits.
- **Finite JSON on every TFM (AUD-SAF-003)**: `1e999` no longer parses to an unbounded
  envelope on .NET 7 while net48 refuses - both fail closed, axis data double-checked.
- **Machine identity trust (AUD-SAF-004)**: per-connection fingerprint
  (`boards[0].uniqueId`, else a labelled configuration hash), persisted expectation in
  the .gh, first connection baselines, reconnects reprobe, mismatch = diagnostic-only
  (presentation + transaction-side refusal; E-STOP stays live), "Trust connected
  machine" context-menu acceptance behind undo. Deviation from the spec: no M122 middle
  leg (it perturbs the shared reply drain at connect; flagged for maintainer review).
  The transaction gate re-derives a permissive cached trust state against the current
  expected/observed pair, closing the remaining expectation-change race. Connect
  components sharing one host must agree on the persisted machine identity: conflicting
  expectations fail closed with an explicit conflict (never last-writer-wins) until the
  operator accepts the connected machine.

## 4. Components & performance

- **Async file I/O (AUD-PERF-001)**: G-code Save/Restart/pump-CSV, Overhang CSV, RSM
  read/export run in cancellable background workers
  (`Ui/BackgroundFileWork`); last good outputs replay while pending, rising-edge and
  write-on-change semantics preserved. Completion passes the heavy/manual compute gate,
  token sources are disposed, and transient failures can be retried. Approved timing
  change: written/saved report on the completion re-solve.
- **IAMLab Version** (new, `1 Slice`, GUID index `0028`→`4bcb`): assembly-sourced
  version/build date/runtime + summary; strictly opt-in update check (no request while
  `check=false` or unconfigured; one bounded HTTPS query per session once a release
  manifest URL is set at release time). Its three-second budget covers the streamed body,
  not only response headers. Core `SemVer` + `UpdateCheck` unit-tested.

## 5. Release pipeline

- **Clipper2 exact-source rebuild (AUD-REL-002)**: `third_party/Clipper2` (upstream tag
  `Clipper2_1.4.0`, identical strong-named identity) replaces the NuGet binary that
  embedded its author's local path.
- **.3dm revision-history sanitization (AUD-REL-005)**: the maintainer's Windows
  username sat UTF-16LE-encoded in both robot models' revision history (stamped by the
  2026-07-17 rebuild itself, invisible to ASCII scans); `tools/sanitize_3dm_revision.py`
  neutralized it CRC-correctly with geometry verified identical.
- **`tools/release.ps1` (AUD-REL-001/003/004)**: candidate/public packaging - clean
  zero-warning build, tests, allowlisted `net48/`+`net7.0/` staging, curated manifest,
  ASCII+UTF-16 PII scans of stage AND archives, `dist/send-…zip` plus a committed-only
  source export. The final source ZIP is scanned too (ASCII, UTF-16LE and UTF-16BE), the
  package icon is required, and duplicate sanitizer intermediates are forbidden. Auto-Yak
  on ordinary builds is now opt-in. Public mode also requires HTTPS project/update-manifest
  URLs and explicit owner-gate confirmation, so an untested or update-unconfigured build
  cannot be mistaken for the publishable package. RELEASING blockers 2b (arm
  mesh provenance pinned to visose/Robots `79f7b4de`) and 6 (TUHH/IDAC authority) closed;
  stale version text removed (AUD-DOC-001).

## 6. Final test round (docs/dev/FINAL-TEST-ROUND_v2.6.0.md, section 3.1)

- **Spiral infill (3.1.4)**: `infill = 3` emitted the concentric rings unchanged. New
  `Spiral.Inward` blends each ring into the next by arc-length fraction, so one
  continuous bead spirals from the wall to the centre with no seam and no hop.
- **Fermat infill (3.1.4)**: the component appended the corridor spans as separate open
  curves ("three open circles"). `Fermat.Paths` now joins them into the one continuous
  Fermat path the wiki promised; start and end sit on the outermost rings.
- **Infill connects to the boundary (3.1.4)**: concentric, spiral and fermat start at the
  point nearest the innermost wall's seam (its end point), so the wall-to-infill handoff
  is one bead spacing. Ring sets with several islands per depth degrade to independent
  rings (never an extrusion across the gap).
- **Adaptive layer height (3.1.7)**: slope sampling moved to Core
  (`Levels.SlopeFromMesh`, unit-tested on a capped hemisphere): area-weighted instead of
  face-count-weighted, exactly horizontal faces (caps, flat tops) no longer pull a band
  toward "flat", empty bands borrow their neighbour. `info` now reports the layer count
  and the realised layer-height range.
- **Spiralize with walls (3.1.6)**: `info` states that only the outer contour is
  spiralized and that `wallCount`/`infill` are ignored.
- **Brep meshing group removed (3.1.4 note)**: `meshDensity`, `meshMaxEdge`, `meshMinEdge`
  and the "Brep meshing inputs" group are gone; Breps always mesh with the
  tolerance-driven default. Saved files that had the group enabled open without it.

## 7. Final test round, part 2 (Result column + hardware rows 5.x, 2026-09-02, branch `final-test-round-fixes`)

- **Restart file no longer emits `G17` (5.23)**: `RestartModalState` restores a plane word only when
  the source job carried one (`PlaneExplicit`); the fail-closed parser accepts bare `G17/G18/G19`
  as no-op modals. Restart files of generated jobs upload and start again.
- **Duet footer keeps the machine homed (5.8)**: the DuetRrf footer omits `M84 ; steppers off`
  (RRF clears the homed flags on M84, so every component demanded a new homing after each print);
  `G28` at the end and the Marlin footer are unchanged.
- **Print log can be cleared (5.20)**: IAMLab Duet Live has a right-click item "Clear print log"
  that resets the session recorder and the component's cached rows/trail; the CSV in `logFolder`
  is not touched.
- **Print-order socket removed (3.1.11)**: objects are sliced in input order; the `multiobj` group
  is gone, saved files with the group active open without it.
- **`robot` always visible on IAMLab G-code (5.27)**: the socket moved from the optional `robotdef`
  group to the core inputs; unwired behaviour is unchanged.
- **GraphMapper `clip` (3.2.4)**: both states pin out-of-domain inputs to the graph edges by design
  (`GraphMap.Evaluate` clamps); the socket description now says so, a test documents it.
- **Wording (3.1.6)**: the spiralize fallback states the island count and layer; no user-visible
  "bead" in the touched components (now "path"/"layer").
- **Zigzag infill is one connected path (3.1.4)**: scan rows are joined at the nearest end when the
  connector stays inside the region, all rows are clipped in one Clipper call (was one call per row),
  and `Infill.ZigzagSpans` takes an optional wall anchor so the path can start on the innermost wall.
  Wiring the anchor into IAMLab Slice is still open (`SlicerComponent.cs:153`).
- **IAMLab Duet Print Console (new, 7-Print, 5.17 / 5.24 / 5.25)**: one external WinForms window
  (Connect, Home, Home X/Y/Z with a confirmation, Upload, Start, Pause, Resume, Stop, Reset, E-STOP,
  clearable console view, calibration list with Go to) fed by `gcode`, `host`, `password`, optional
  `robot` and `points`, `open` (rising edge opens or focuses the one window), `live` and an optional
  `jobName`; the arm simulation stays in the Rhino viewport. Upload, Start and Home run the gates of
  Duet Print / Duet Jog inside the command transaction; Go to plans one straight jog move (SCARA
  only). Outputs `status`, `state`, `progress`, `pos`, `homed`, `jobFile`, `log`, `info` come from an
  immutable `PrintConsoleState` reduced in Core from the session change stream and re-solve only
  when a value changed, at most once per second, never with `live` off. Closing the window with
  `live` off releases the component's lease; the connection ends only when no other 7-Print
  component holds it. Guide: `docs/user-guide/print-console.md`. Machine test pending
  (FINAL-TEST-ROUND rows 5.28 to 5.42).
- **Shared print gates extracted**: the upload/start gate chain of IAMLab Duet Print
  (`Core/Duet/JobSafety.cs`) and the verified homing of IAMLab Duet Jog
  (`IAMLabSlicer/Duet/DuetHoming.cs`) are one code path for the components and the console;
  Core tests `PrintConsoleStateTests`, `PrintConsoleExpirePolicyTests`, `JobSafetyTests`.

- **Adaptive layers with spiralize (3.1.7)**: the helix now follows the adaptive levels; the
  spiralize branch rebuilt planar levels and climbed `layerHeight` per turn, so a half sphere got one
  height. Core `Levels.Adaptive` was already right (test `Row317_HalfSphere_Adaptive_ThickAtBase_ThinAtTop`).
- **Conical mode on round objects (3.1.8)**: outer rings of a surface of revolution stay horizontal by
  design (a radial shear moves a whole circle equally), but inner walls and infill were built planar
  at the ring's Z, so mode 1 looked like a no-op. `Core/Slicing/LayerBuilder.BuildConical` builds
  in the sheared frame and maps back, and `Conical.InverseContourRefined` inserts points where a
  straight move would sag more than 0.05 mm below the cone (a zigzag span through the axis sagged
  7 mm). The `coneAngle` description explains the fold above `R*cos(angle)`.
- **Heat mode speed (3.1.9)**: the sparse Laplacian was assembled through the indexer (O(nnz^2)
  inserts, twice per solve); `SparseMatrix.OfIndexed` cuts 180k faces from 11.7 s to 1.8 s
  (`Row319_HeatField_180kFaces_UnderCeiling`). Domes still look planar by design (`HeatV2` sets
  lambda 0 when the planar stagger already exceeds the 30 degree cap).
- **Duet Live arm hidden while unhomed (5.17)**: `HideArmWhileUnhomed` skips the posed arm (bed,
  extrusion and trail stay) whenever an axis is unhomed, which covers the header `G28` that drew the
  arm diving into the bed; `info` states the reason. Hardware-unverified.
- **Robot Simulation J1 axis (robot.xml)**: the J1 pivot is re-centred on the Z-rail's own axis
  (bbox centre of the `LinearRailZ` brep, equal to the J2 pivot XY); the old value was the arm's
  pivot hole 32 mm beside the column, so the rail swung about a point next to itself. J1/J3 `home`
  and link1 `axialScale` are recomputed from the pivots; drawing only, kinematics unchanged.
  Pinned by `ShippedRobotModelTests`; viewport check open.
- **Wording (3.1.6, remaining)**: Print Stats, Robot, Robot Simulation and Duet Live
  descriptions say "extrusion"/"layer" instead of "bead"; socket names unchanged.

## Compatibility

No shipped GUID, socket, default or valid-input numeric result changed on millimetre
documents, except the IAMLab Slice changes of section 6: `infill = 3` and `4` now yield
one path per layer instead of one curve per ring/span, and the optional meshing sockets
no longer exist. Saved definitions open and solve unchanged; the unwired legacy G-code
frame, Potterbot Duet defaults, Desirability alternatives semantics and slicer-only
operation are untouched. New sockets appear only on the new IAMLab Version and IAMLab Duet Print
Console components. Conical mode (`mode = 1`) now yields walls and infill on the cone surface (they
were planar), and the drawn SCARA rotates about the rail axis in the viewport (`robot.xml` pivot).
Section 8 changes the text of the Duet Live `layers` lines (readable rows instead of
`layer=..., start=..., ...`); anything that parsed those key=value lines must read the CSV
`log` output instead, which is unchanged. Zigzag infill (`infill = 1`) now starts at the wall
seam, so the first infill vertex moves; geometry otherwise identical. The Print Console's `pos`
output is now in document units (mm documents unchanged) and its `points` input is read in
document units; the window's position line shows machine millimetres.
