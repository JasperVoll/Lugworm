# The Legend component's palette registry

Moved verbatim out of `../ARCHI.md` section 8 during the 4.4.0 documentation
compaction and rewritten for 5.0.0. ARCHI keeps what the Legend is and that the palettes
are generated; the registry's sources, numbering, aliases and exceptions live here. Every
palette with its number and colours: [Legend palette table](legend-palette-table.md).

**The registry** (5.0.0): `ColorSchemes` is a facade over `ColorScheme` records (name, family, kind `Sequential | Diverging | Qualitative | Cyclic`, stops, aliases). It holds **35 palettes chosen for engineering use**: perceptual and single-hue ramps for magnitudes, diverging maps for signed values, cyclic maps for angles, qualitative sets for classes. 32 are matplotlib colormaps, `rainbow` and `Okabe-Ito` are R `grDevices` palettes, and `traffic` is Lugworm's overhang three-step. `tools/gen_color_schemes.py` writes `Core/Analysis/ColorSchemeData.cs` and the palette table from matplotlib and the ported R formulas; `tests/tooling/test_color_schemes_sync.py` pins both files to the script.

**Frozen numbers.** The generator's `REGISTRY` list is the one source of order, and a palette's number is its position: `ColorSchemeData.Numbered`, and therefore `ColorSchemes.All[n]`. Numbers are append-only. A new palette takes the next number, a removed one leaves its number unused, and the sync test pins the whole name-to-number list so a reorder fails. `ColorSchemes.Resolve`/`IsKnown`/`At` accept a number as text (`"14"`, invariant integer, `0` to `34`); `ColorSchemes.Normalize` turns it into the name before a `LegendSpec` is built, so the `iamlab-legend:v1` wire keeps carrying names and its format did not change. The Legend's `scheme` value list offers all 35 in number order, labelled `Kind: name (n)`, with the bare name as the value, so settings files and saved value lists keep matching by name.

**Core-owned palettes.** `plasma`, `viridis` and `traffic` are numbered by the generator but **not** generated: `plasma` and `viridis` keep routing to `PlasmaColorScale` / `DeviationColorScale` (by name or by number), so Interlayer Time and Live View colours never move with a matplotlib release, and `traffic` is defined in the facade. The Lugworm icon ramps are gone: `blues`/`greens`/`greys` are the matplotlib maps. 5.0.0 moved three aliases whose targets left the registry: `pinks` now resolves to `Purples` (was `RdPu`), `ambers` to `Oranges` (was `YlOrBr`), `gray`/`grays` to `Greys` (was R `gray`).

**Removed in 5.0.0** (112 palettes): all 86 ggsci palettes (journal, TV-theme and UI-kit ramps, and with them the `tools/color_schemes/ggsci.json` snapshot and the `--import-ggsci` path); 18 matplotlib maps (`YlOrBr`, `OrRd`, `PuRd`, `RdPu`, `BuPu`, `GnBu`, `PuBu`, `PuBuGn`, `BuGn`, `YlGn`, `PRGn`, `RdGy`, `tab20b`, `tab20c`, `Set3`, `Pastel1`, `Pastel2`, `Accent`); 8 R palettes (`R3`, `R4`, `ggplot2`, `heat`, `terrain`, `topo`, `cm`, `gray`). Every kept palette's stops are byte-identical to 4.4.0. A removed name no longer resolves: the Legend warns and draws blues, and a wire naming one falls back to its own colours or blues as any unknown scheme always did.

A qualitative palette hands its colours to classes one by one; a ramp is sampled. `LegendSpec.Stops` carries positioned custom ramps (`stops=` on the wire, parse-tolerant), which is how the Legend's `gradient` input reproduces Grasshopper's Gradient component grips exactly; the `mesh` and `frames` outputs are preview-hidden (`HideParameter`) because the component draws the legend itself.
