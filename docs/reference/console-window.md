# The Duet Console window

Moved verbatim out of `../ARCHI.md` section 15 during the 4.4.0 documentation
compaction. ARCHI keeps the rules (the window never offers what the transaction would
refuse; the console is a persistent command shell); the detail lives here.

- **The window can never offer what the transaction would refuse** (since 3.0.0): `PrintConsoleButtons.Enabled` consumes the session's trust refusal, the home-macro probe, the unresolved control profile and the fail-closed Cartesian envelope list, because every one of those refuses inside `RunGatedCommandAsync`. The homing predicate is exactly `DuetHoming.PreflightRefusal`: refuse only when the probe **completed** and the axis has no macro, since homing is the recovery path out of an unknown configuration. E-STOP is the one control that is never trust-gated — it bypasses the command queue entirely — and it is a native WinForms button, along with Reset, docked outside the Skia surface: a missing native kills the CPU and GL surfaces alike, so the two controls that must survive that are not drawn by Skia at all
- **The console is a persistent command shell** (2026-09-07, per the console UI design note of 2026-09-04, archived in `../Lugworm_to_delete/docs/superpowers/specs/`): rail navigation (Dashboard, Control, Job, Terminal, Logs), a status header, page renderers under `Ui/Console/Pages/`, a graphite theme, a stroked icon family, `ConsolePrimitives`/`ConsoleLayout`, and `ConsoleInteractionState` for hover/press/navigation transitions that run only while active (a persisted reduced-motion preference removes them). The dashboard's one primary action is `ConsoleNextAction` (Core, tested): it names the page action's id and gate and never sends. Window bounds persist user-globally (`ConsoleSettings` under `%LOCALAPPDATA%\Lugworm`); the page never does. Parity fixes of the same date: Validate has its own offline gate (`ButtonSet.Validate`), Start's label and command follow the projected `DryRun`, the go-to list is paged and a replaced list clears the selection, a held jog is released on every lost mouse-up path plus independently on the component (`CancelJogHold`), both Skia surfaces are guarded around the whole `OnPaint` (SkiaSharp issue 2676), and a console-entered `M999` is re-checked against the transaction snapshot. Source-bound guards: `tests/tooling/test_console_parity.py`
- **Closing the window keeps the session** (2026-09-23): the console takes its lease when a session exists for its host and the window is shown or `live` is on, and keeps it while the window is hidden. It lets go only when the component is removed, its document closes, its `host` input names another machine, or the operator presses Disconnect, which closes the host for every leaseholder and leaves the window offering Connect. Releasing on hide stopped the session whenever the console held the only lease: the always-on job log of a running print ended there, the rest of the print was recorded as an external run, and the E-STOP had no target until the next Connect. Opening or fronting the window re-evaluates the rule at once, so a session another lease kept alive shows as connected without a re-solve. `live` still decides only whether changed outputs re-solve the canvas
- **Console dialogs block the footer while they are open** (known limitation, 2026-09-23): the per-axis homing confirmation, the Export copy save dialog, the Change location folder picker and the Discard confirmation are modal to the console window, so while one is open the whole window takes no input, the native E-STOP and Reset included. The Logs page can be used during a print: dismiss the dialog first, or use the machine's physical switch. The dialogs were deliberately not restructured for 0.1.0-beta
- **Two consoles look alike at window level** (known limitation, 2026-09-23): every console window has the title "Lugworm Duet Console" and restores the same saved position, so a second console, from another component or for another host, opens exactly on top of the first. The host is shown only in the drawn status header; move one window aside before working with two
